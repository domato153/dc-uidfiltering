# Evidence-based UI separation

This note records the external evidence used to shape the DCUF refactor and the concrete adaptation for a mutating Tampermonkey userscript. It is a design input, not a substitute for repository receipts or live canary evidence. Sources were rechecked on 2026-09-06.

## Evidence translated into repository rules

| Evidence | Supported principle | DCUF application | Deliberate limit |
| --- | --- | --- | --- |
| [Alistair Cockburn, Hexagonal Architecture](https://alistair.cockburn.us/hexagonal-architecture/) | Application behavior can be isolated behind ports while UI, storage, and tests act as adapters. | `UiPort`, `HostSurfacePort`, immutable snapshots, typed intents, and application-owned GM effects define the boundary. Presentation cannot reach GM APIs, filter decisions, or document-global observers. | The repository does not add a framework or force every pure helper behind an interface. Ports exist only at consequential ownership boundaries. |
| [Martin Fowler, Branch by Abstraction](https://martinfowler.com/bliki/BranchByAbstraction.html) and [Jez Humble's production UI migration case](https://continuousdelivery.com/2011/05/make-large-scale-changes-incrementally-with-branch-by-abstraction/) | A stable abstraction permits incremental replacement while the system remains working; transitional architecture needs an exit strategy. | Keep legacy behavior behind a port, migrate one surface family per PR, select one owner at composition time, then remove the old owner in the same PR that activates the replacement. Every `mixed` registry component must declare a machine-validated exit contract. | Old and new mutating UI implementations are never injected together into one page for comparison. Separate artifacts and contexts are used instead. |
| [GitHub Scientist](https://github.com/github/scientist) | Control/candidate observations can expose semantic differences. | Compare immutable control and candidate artifacts with identical seeds and explicit semantic receipts. | Scientist's in-process pattern is not used directly because DOM, GM storage, observers, timers, and network effects mutate state. |
| [Playwright browser-context isolation](https://playwright.dev/docs/browser-contexts) | Fresh contexts prevent leaked cookies, storage, and page state from contaminating tests. | Control and candidate run in distinct fresh browser contexts/processes; teardown must return owned listeners, observers, subscribers, timers, and queues to baseline. | A context reset does not make a synthetic fixture equivalent to the live site; canary remains mandatory. |
| [Behavior-preservation systematic mapping](https://arxiv.org/abs/2106.13900) | No single preservation strategy is sufficient across legacy transformations. | Combine static boundary checks, dynamic characterization, differential receipts, metadata/storage checks, performance structure checks, manual review, and exact-artifact canary. | Pixel equality and wall-clock timing alone do not authorize a refactor. |
| [Google mutation-testing study](https://research.google/pubs/long-term-effects-of-mutation-testing/) | Mutation testing can reveal weak tests and is coupled to real defects at scale. | Mutate head lineage, evidence binding, runtime guard, differential identity, presentation boundaries, and oracle inputs; require each mutation to fail for the intended reason. | The project does not add a general mutation-testing dependency or chase mutation score as a goal. |
| [Microsoft Coyote](https://microsoft.github.io/coyote/) | Systematic exploration of ordering, delays, failures, and timeouts finds stateful bugs ordinary runs miss. | Exercise pending GM reads/writes, rejected writes, duplicate initialization, rerender, delayed popup, visibility/pageshow, teardown, and bounded retry orderings. | Coyote itself is not a JavaScript dependency and these tests are evidence, not a formal proof. |
| [Murphy, Notkin, and Sullivan, Software Reflexion Models](https://dl.acm.org/doi/10.1145/222132.222136) | Comparing an intended architecture model with implementation relations exposes conformance and divergence. | `architecture/registry.json` maps real sources, contracts, relations, invariants, current debt, and transition exits; AST/build fitness checks compare code and assembly against it. | The registry records observed mixed ownership honestly instead of presenting the target structure as current fact. |
| [Google Testing Blog, Hermetic Servers](https://testing.googleblog.com/2012/10/hermetic-servers.html) | Tests that depend on shared external services become slow and flaky; hermetic dependencies improve reproducibility. | Hosted CI uses local fixtures and servers. Redacted live structural probes update provenance-tagged fixtures, and exact-artifact manual canary covers the gap. | CI does not scrape authenticated DCInside, bypass bot controls, or call an unavailable live state a pass. |

## Per-surface application protocol

1. Freeze the control artifact, fixture/harness hashes, selected semantic observations, and live provenance before changing a surface.
2. Record current state/effect/DOM/CSS/listener ownership in the registry. A `mixed` component must state its concrete exit criteria.
3. Introduce or reuse a port around the consequential boundary. Keep GM, filtering, scheduling, and host DOM effects outside presentation.
4. Characterize the legacy adapter first. Build the replacement behind the same port without changing visible design or public storage/event behavior.
5. Build control and candidate separately. Never run both mutating implementations in the same page or storage namespace.
6. Compare filtering, host-node identity/order, forms/native handlers, GM before/after values, requests, events, lifecycle ownership, focus/hit testing/geometry, console errors, and hot-path structural calls.
7. Exercise relevant order/failure combinations, including repeated mount, late host nodes, pending/rejected GM operations, page lifecycle transitions, and teardown/reopen.
8. Route the candidate at composition time and remove the superseded visual/event owner in the same PR. No indefinite dual path or undocumented fallback remains.
9. Promote the registry overlay only when the exit contract is true in code and fitness checks. Regenerate evidence whenever the SUT, oracle, fixture, harness, route, or toolchain binding changes.
10. Run exact-head hosted acceptance, independent upper-layer audit, and the stage-specific exact-artifact live canary before accepting the slice.

## Evidence identity and portability

Source evidence is semantic text, so CRLF and LF checkouts bind to the same canonical digest. Binary files and built userscript artifacts remain byte-exact. The binding includes product/build inputs, the registry, candidate state, gates, harness, fixtures, pinned toolchain inputs, and the proof/oracle implementation itself. Receipts with missing, extra, or mismatched binding fields are stale. CI manifests must record a real Playwright version and all expected artifacts; `null` tools or missing files cannot produce a passing manifest.
