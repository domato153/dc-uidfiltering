## What to read and update

Keep stable policy in AGENTS, current facts in CURRENT, exactly one objective/why/expected/stop action in NEXT, and detailed contracts/evidence at their existing paths. Update on a meaningful result, decision, blocker or handoff; do not log every command or create a snapshot after every file edit. Completed task inputs leave NEXT. An unfinished proposal stays explicitly planned/unknown, never accepted by implication.

The active packet retains adopted decisions only. When a decision is replaced, update its active statement and retain one short historical guard with reason and reopen trigger. Retrieve the detailed rationale only when that trigger or a specific cause matters. Fresh contradictory evidence requires explicit reconciliation; repetition of an old chat is not new evidence.

For a new thread, give its private prompt the exact active worktree's INDEX path and request: read CURRENT/NEXT, fresh-check root/branch/HEAD/status and inspector, resolve meaningful drift, report ACCEPTED or STALE_REPLAN, then perform the bounded next action. Do not paste the full conversation or create a new user-visible task without an explicit request. A fork inherits context and is not a cold-read rehearsal.
