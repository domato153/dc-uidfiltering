## Operating rules after this change

Use one coherent, reviewable owner/behavior unit; run related local product checks before publication and let the publisher own the final `verify-repo all` instead of running that same final check immediately beforehand. A commit is not needed to run local tests. CI pending may coexist with independent next work; report pending until its exact SHA is qualified. Retry transport with the existing commit. Full settled-runtime/surface/lifecycle/shared/storage and release boundaries retain their required checks. Architecture ownership changes can still broaden a bounded header route; batch related owner changes rather than bypassing that boundary.

The repository-wide candidate fingerprint remains a conservative continuity/proof identity. It is not a reason by itself to repeat unchanged product tests. Existing globally bound stage receipts are not relabeled as current or rewritten into narrower proof. Narrow report reuse requires unchanged SUT/oracle/fixtures/harness/toolchain and explicit scope; the current work only adds exact-input audit retry, not a general result cache.
