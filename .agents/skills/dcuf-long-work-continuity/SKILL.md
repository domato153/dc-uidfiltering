# DCUF Long-work Continuity

Resolve authority in this order: fresh remote refs and current HEAD, tracked current state, build/registry contracts, then historical notes or chat.

1. Recheck branch, commit, worktree status, baseline manifest, active candidate overlay, and generated-artifact state.
2. Read the tracked current-state record and choose one bounded next task. Treat ignored `.codex` as scratch only.
3. Re-run skill and impact routing whenever the task, phase, failure class, verification runtime, or release boundary changes.
4. Update accepted state only after its checks and commit exist. Keep candidate facts separate and mark superseded current-looking records historical.
5. Record exact result SHA, validations, stale evidence, unresolved risks, and the next bounded action; omit command diaries and sensitive live data.

Continuity preserves state; it does not authorize commits, pushes, merges, live actions, or releases.
